Drawing a texture 

텍스쳐를 그리는 방법에 대해서 자세하게 알아 보겠습니다.
우선 텍스쳐를 그리는 전체 코드부터 먼저 보겠습니다.

texture.shader 파일
Shader "URPStudy/texture"
{
    Properties
    {
        _BaseMap("BaseMap", 2D) = "white" {}
    }

    SubShader
    {
        Tags { "RenderType" = "Opaque" "RenderPipeline" = "UniversalPipeline" }

        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct Attributes
            {
                float4 positionOS : POSITION;
                float2 uv         : TEXCOORD0;
            };

            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
                float2 uv          : TEXCOORD0;
            };

            TEXTURE2D(_BaseMap);
            SAMPLER(sampler_BaseMap);

            CBUFFER_START(UnityPerMaterial)
            float4 _BaseMap_ST;
            CBUFFER_END

            Varyings vert(Attributes IN)
            {
                Varyings OUT;
                OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
                OUT.uv = TRANSFORM_TEX(IN.uv, _BaseMap);
                return OUT;
            }

            half4 frag(Varyings IN) : SV_Target
            {
                half4 color = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, IN.uv);
                return color;
            }
            ENDHLSL
        }
    }
}

텍스쳐 슬롯 추가

Properties
{
    _BaseMap("BaseMap", 2D) = "white" {}
}

머티리얼 슬롯: _BaseMap이라는 텍스처 슬롯을 만듭니다. 에디터에서 “BaseMap” 라벨로 보이고, 기본값은 흰 텍스처입니다.

의미: 머티리얼에 지정된 텍스처가 셰이더로 전달되며, 이후 샘플링에 사용됩니다.

struct Attributes, Varyings에 UV 좌표에 대한 변수를 추가


struct Attributes
{
    float4 positionOS : POSITION;
    float2 uv         : TEXCOORD0;
};

struct Varyings
{
    float4 positionHCS : SV_POSITION;
    float2 uv          : TEXCOORD0;
};

struct Attributes에서 uv : 메시에 저장된 첫 번째 UV 채널
Varyings에서 uv : 프래그먼트 셰이더로 전달될 UV. 마지막 단계에서 삼각형 내부 픽셀로 보간됩니다.


텍스처를 2D 텍스처로 정의하고 샘플러를 지정

TEXTURE2D(_BaseMap);
SAMPLER(sampler_BaseMap);

TEXTURE2D: 머티리얼의 _BaseMap 텍스처 리소스를 참조합니다.
SAMPLER: 필터링/랩핑 모드 등 샘플링 상태를 나타냅니다.

TRANSFORM_TEX

- TRANSFORM_TEX는 Unity 셰이더에서 매우 자주 쓰이는 편의 매크로입니다.

- UV 좌표에 Material의 Tiling & Offset 값을 적용해줍니다.

- URP에서는 반드시 float4 _XXX_ST를 UnityPerMaterial CBUFFER 안에 선언해야 함

// 실제 매크로 정의 (UnityCG.cginc / Core.hlsl 등에 있음)
#define TRANSFORM_TEX(tex,name) (tex.xy * name##_ST.xy + name##_ST.zw)

직접 쓰는 것 vs TRANSFORM_TEX 쓰는 것 비교
// 직접 쓰기 (TRANSFORM_TEX 매크로와 동일한 결과)
OUT.uv = IN.uv * _BaseMap_ST.xy + _BaseMap_ST.zw;

// 매크로 사용 (가독성 + 실수 방지)
OUT.uv = TRANSFORM_TEX(IN.uv, _BaseMap);

상수 버퍼 (SRP Batcher 호환 되려면):
CBUFFER_START(UnityPerMaterial)
float4 _BaseMap_ST;
CBUFFER_END

역할: 머티리얼별 상수(타일링/오프셋)를 GPU에 효율적으로 업로드합니다. SRP Batcher와 정렬되는 레이아웃입니다.
_BaseMap_ST는 TRANSFORM_TEX에 적용한 변수입니다.
SRP Batcher에 대해서는 마지막에서 자세하게 다시 설명하겠습니다.

버텍스 셰이더 함수:
Varyings vert(Attributes IN) {
    Varyings OUT;
    OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
    OUT.uv = TRANSFORM_TEX(IN.uv, _BaseMap);
    return OUT;
}
  • 화면 변환: TransformObjectToHClip는 오브젝트 공간 → 월드 → 뷰 → 클립 공간으로 변환해 SV_POSITION에 넣습니다.
  • UV Tiling/Offset: TRANSFORM_TEX(IN.uv, _BaseMap)는 머티리얼의 _BaseMap_ST를 이용해 UV에 타일링(_BaseMap_ST.xy)과 오프셋(_BaseMap_ST.zw)을 적용합니다.
프래그먼트 셰이더 함수:
half4 frag(Varyings IN) : SV_Target {
    half4 color = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, IN.uv);
    return color;
}
  • UV 보간 사용: 버텍스에서 넘긴 IN.uv는 픽셀 위치에 맞게 보간되어 들어옵니다.
  • 샘플링: SAMPLE_TEXTURE2D로 _BaseMap을 sampler_BaseMap 상태로 샘플하고, 결과 색을 그대로 출력합니다.
  • SV_Target: 렌더 타겟(보통 컬러 버퍼)에 쓰이는 픽셀 컬러입니다.

유니티 6에서 SRP Batcher

유니티 6(Unity 6)에서 SRP Batcher는 URP/HDRP의 핵심 최적화 기술로, 셰이더 변수 업데이트 속도를 향상시켜 CPU 드로우콜 부하를 줄입니다. 여러 매테리얼이 동일한 셰이더를 사용할 때 효과적이며, 유니티 6에서는 새롭게 추가된 GPU Resident Drawer와 병용되어 극적인 렌더링 성능 향상을 제공합니다.

유니티 6 SRP Batcher 핵심 정리
  • 작동 원리: 드로우콜 자체의 수를 줄이는 것이 아니라, 매테리얼 데이터(SetPass Call)를 GPU 메모리에 상주시켜 CPU가 렌더링 상태를 변경하는 비용을 최소화합니다.
  • 유니티 6에서의 위치: URP/HDRP 프로젝트 설정에서 기본 활성화되어 있으며, 특히 많은 오브젝트를 화면에 그릴 때 필수적인 기술입니다.
  • 호환성: 커스텀 셰이더의 경우 SRP Batcher 호환성 코드를 포함해야 동작합니다.

최적화 팁:
  • 동일한 셰이더를 사용하는 매테리얼을 최대한 공유하여 배치 효율을 높입니다.
  • Skinned Mesh Renderer도 지원하지만, 2D 셰이더 사용 시 Metal 오류가 수정된 최신 6000.x 버전을 사용해야 합니다.
머티리얼 프로퍼티 CBUFFER: 모든 머티리얼의 프로퍼티(color, float, vector 등)는 오직 하나의 CBUFFER 안에 선언되어야 하며, 이름은 UnityPerMaterial이어야 합니다.

SRP Batcher 호환 셰이더 예시 (HLSL)

// ... 다른 셰이더 코드들 ...

// 1. 모든 프로퍼티를 CBUFFER_START(UnityPerMaterial) 안에 묶습니다.
CBUFFER_START(UnityPerMaterial)
    float4 _BaseColor;
    float4 _BaseMap_ST; // Tiling and Offset
    half _Cutoff;
    // 필요한 다른 머티리얼 프로퍼티들...
CBUFFER_END

// 2. 텍스처는 CBUFFER 안에 넣지 않습니다. (SRP Batcher가 처리)
TEXTURE2D(_BaseMap);
SAMPLER(sampler_BaseMap);

// ...

SRP Batcher 호환성 체크리스트
  • MaterialPropertyBlock 미사용: SRP Batcher는 MaterialPropertyBlock을 사용하는 렌더러와 호환되지 않습니다.
  • 텍스처는 CBUFFER 제외: 텍스처 변수는 CBUFFER_START와 CBUFFER_END 바깥에 선언해야 합니다.
  • 변수 타입 일치: Properties 블록에서 정의한 변수명과 CBUFFER 내의 변수명이 동일해야 합니다.
  • Multi-pass 셰이더: 셰이더에 여러 패스(Pass)가 있다면, 모든 패스에서 동일한 UnityPerMaterial 구조를 사용해야 합니다.
  • Meta Pass: 라이트맵 베이킹을 위한 Meta Pass에서도 CBUFFER 구조가 깨지지 않도록 해야 합니다.
셰이더 호환성 확인 방법
  1. 프로젝트 설정에서 SRP Batcher를 활성화합니다.
  2. 작성한 셰이더 파일을 Inspector창에서 클릭합니다.
  3. Inspector 하단에 "SRP Batcher: compatible"이라고 표시되면 호환되는 것입니다.
  4. 만약 "not compatible"이라면, CBUFFER_START 블록이 제대로 정의되지 않았거나, MaterialPropertyBlock을 사용하는 오브젝트가 씬에 있는 것입니다.
