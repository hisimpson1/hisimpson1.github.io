Flutter StatefulWidget의 구조적 이해

1. StatefulWidget과 setState 개념

Flutter에서 화면은 '위젯(Widget)'의 조합으로 이루어집니다. 그중에서도 데이터에 따라 모습이 변하는 것을 StatefulWidget이라 부릅니다.

  • StatefulWidget: 상태(데이터)를 가질 수 있는 위젯입니다.
  • setState(): "상태가 변했으니 화면을 새로 그려라"라고 Flutter 엔진에 보내는 알림 신호입니다.

2. 왜 반드시 클래스를 2개로 나누어 쓰나요?

초보자가 가장 의아해하는 부분입니다. "그냥 클래스 하나에 변수랑 화면 코드를 다 넣으면 안 될까?"라는 의문이 들 수 있죠. 하지만 여기에는 Flutter의 성능 최적화 전략이 숨어 있습니다.

① 위젯(Widget)은 소모품입니다

Flutter에서 위젯 클래스(CounterPage)는 매우 가볍고 **불변(Immutable)**한 객체입니다. 화면이 1초에 60번 바뀐다면, 위젯 객체도 1초에 60번씩 새로 생성되고 버려질 수 있습니다. 만약 이 클래스 안에 count 데이터를 저장한다면, 화면이 바뀔 때마다 데이터가 초기화되어 버릴 것입니다.

② 상태(State)는 유지되어야 합니다

반면, _CounterPageState 클래스는 위젯이 화면에 떠 있는 동안 메모리에 계속 유지됩니다. 위젯 껍데기가 수백 번 갈아치워져도, 알맹이인 '상태 객체'는 그대로 살아남아 count 숫자를 안전하게 지킵니다.

정리하자면:
1. CounterPage (Widget): "이 화면은 상태가 필요한 화면이다"라는 것을 정의하는 설계도/이름표 역할 (자주 교체됨)
2. _CounterPageState (State): 실제 데이터와 화면을 그리는 로직을 담은 실행 엔진 역할 (오래 유지됨)

3. 두 클래스의 역할 비교

구분 위젯 클래스 (CounterPage) 상태 클래스 (_CounterPageState)
불변성 불변 (Immutable)
내부 필드는 모두 final이어야 함.		 가변 (Mutable)
변수 값을 자유롭게 변경 가능.
수명(Lifecycle) 매우 짧음
부모 위젯이 재빌드되면 같이 새로 생성됨.		 길음
화면에서 완전히 제거될 때까지 유지됨.
핵심 메서드 createState()
상태 객체를 생성하여 연결함.		 build() / setState()
화면을 구성하고 변화를 처리함.

4. 전체 소스 코드 (main.dart)

import 'package:flutter/material.dart';

void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: CounterPage(),
    );
  }
}

// 1. 위젯 클래스: 상태를 '가질 수 있음'을 정의 (이름표)
class CounterPage extends StatefulWidget {
  @override
  _CounterPageState createState() => _CounterPageState();
}

// 2. 상태 클래스: 실제 데이터(상태)를 보관하고 화면을 그림 (엔진)
class _CounterPageState extends State<CounterPage> {
  int count = 0; // 위젯이 재생성되어도 이 값은 유지됩니다.

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text("StatefulWidget 이해")),
      body: Center(
        child: Text(
          '현재 숫자: $count',
          style: TextStyle(fontSize: 30),
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          // setState를 호출해야만 build()가 다시 실행됩니다.
          setState(() {
            count++; 
          });
        },
        child: Icon(Icons.add),
      ),
    );
  }
}
